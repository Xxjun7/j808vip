你可以直接複製並儲存以下這段「提示詞摘要」，下次回來修改時貼給我，我就能立刻接續目前的進度：

> 我們目前正在維護一個基於 Firebase Cloud Functions / Next.js API 的翻卡/抽獎後端程式碼。
> **目前的的核心邏輯與架構：**
> 1. **交易與併發保護**：使用 Firestore Transaction 搭配最多 3 次自動重試機制，並有預熱防呆 (`warmup`)。
> 2. **動態機率分配（無狀態/跨天累積）**：
> * 每次抽獎時，以當下的剩餘總遊戲次數 (`currentChances`) 作為分母，動態計算機率。
> * 抽中後「出現一次、扣除一次、即時更新」，支援分批與跨天抽獎。
> 
> 
> 3. **抽獎優先順序（瀑布流攔截，不互相稀釋）**：
> * **第一層**：動態判定「指定獎品/特獎」（依剩餘數量與總次數比例計算，中獎即扣除該指定庫存）。
> * **第二層**：動態判定「保底機制」（依保底剩餘次數與總次數比例計算，中獎即扣除 `guaranteeCount`，從預設池隨機給獎，不跟未中獎碰撞）。
> * **第三層**：一般中獎率 (`winRate`) 判定。
> * **第四層**：未中獎（回傳 0）。
> 
> 
> 4. **即將擴充的目標**：後續需要將固定金額的指定獎品，改為**支援自行輸入名稱與數量的 5 個自訂特獎（Custom Prizes）**。
